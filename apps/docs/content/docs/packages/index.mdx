---
title: Supported Packages
description: Every package and class mLaTeX reads, how each one is supported, and what happens with the rest.
---

mLaTeX reads **509 packages** and **15 document classes**, plus LaTeX's standard `article`, `report` and `book`. Each one is checked by a small document of its own that uses what the package is loaded for, and mLaTeX's tests fail if any of them reports an error or an unknown command.

## How a package is supported

### A module of its own

143 packages are written in mLaTeX's language and compiled into the program, their commands defined over mLaTeX's own primitives.

### Built in

333 packages need nothing loaded, because mLaTeX already does their job. `graphicx` (`\includegraphics` is part of mLaTeX), `xcolor`, `inputenc`, `microtype` and the font packages are here. Any of their commands a document uses that mLaTeX does not define comes from the glossary.

### Under another name

33 packages are another one under a newer or older name, and load that one.

### Packages that are not listed

`\usepackage{anything}` never stops a document. A package mLaTeX does not know is marked as loaded and named in a warning, and its commands are looked up in the **glossary**, about 630 commands from CTAN packages with no module of their own, the first time the document uses them. A command neither knows is an error where it is used, as in LaTeX.

<Callout type="info">
  Being listed means a package loads and its common commands set text, not that every feature of it is drawn. Where a package is only partly supported, its entry in the reference says so.
</Callout>
