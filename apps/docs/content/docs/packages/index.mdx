---
title: Supported Packages
description: Every package and class mLaTeX reads, how each one is supported, and what happens with the rest.
---

mLaTeX reads **509 packages** and **14 document classes**, plus LaTeX's standard `article`, `report` and `book`. Each one is checked by a small document of its own that uses what the package is loaded for, and the engine's tests fail if any of them reports an error or an unknown command.

A package is supported in one of three ways:

* **A module of its own** (143): the package is written in mLaTeX's language and compiled into the program, its commands defined over the engine's own primitives.
* **Built in** (333): the engine already does the package's job, so there is nothing to load. `graphicx` (`\includegraphics` is part of the engine), `xcolor`, `inputenc`, `microtype` and the font packages are here. Any of their commands a document uses that the engine does not define comes from the glossary.
* **Under another name** (33): a package that is another one under a newer or older name loads that one.

## Packages that are not listed

`\usepackage{anything}` never stops a document. A package mLaTeX does not know is marked as loaded and named in a warning, and its commands are looked up in the **glossary**, about 630 commands from CTAN packages with no module of their own, the first time the document uses them. A command neither knows is an error where it is used, as in LaTeX.

<Callout type="info">
  Being listed means a package loads and its common commands set text, not that every feature of it is drawn. Where a package is only partly supported, the table says so.
</Callout>

## Adding a package

A package is a folder with one file in it, `name/main.mtex`, and a document finds it beside itself without rebuilding anything. See [Writing Packages](/docs/packages/writing).
