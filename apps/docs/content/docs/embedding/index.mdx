The `mlatex` command is a thin layer over a library, and the same library is available to your own programs. A program can make documents without running a second process, without writing files, and with data only it has.

## Why embed

* **Values.** Hand a document named values, such as a customer's name or an invoice number, and read them with `\variable{name}`.
* **Commands your program answers.** Define a command such as `\balance{account}`. When the document reaches it, mLaTeX calls your function with the arguments the document wrote, and sets what it returns.
* **Files from memory.** Hand in a package, a chapter or a picture you just drew, under the name the document uses for it. Nothing touches the disk.
* **The PDF as bytes.** Get the finished PDF back in memory, to send, store or stream.

A document asks for what it needs:

```latex
\usepackage{letterhead}
Billed to \variable{customer}. Balance on account A-1042: \$\balance{A-1042}.
\includegraphics[width=\textwidth]{chart.png}
```

## Sessions

Every binding works with a **session**: where the fonts are, plus the values, commands and files every document it makes is handed. A session keeps what it is given from one document to the next until it is replaced or taken back, so a program that makes a thousand invoices sets up its letterhead once.

| Operation              | What it does                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `set` / `unset`        | Give or take back a value read with `\variable{name}`                                                               |
| `define` / `forget`    | Give or take back a command the program implements                                                                  |
| `provide` / `withdraw` | Hand in or take back a file: a package (`letterhead/main.mtex`), an input (`terms.mtex`) or a picture (`chart.png`) |
| `typeset`              | Make a PDF from a document held in memory                                                                           |
| `pdf`                  | The last PDF made                                                                                                   |
| `error`                | What went wrong, one error per line                                                                                 |
| `offline`              | Keep documents off the network                                                                                      |

A file handed in is found before one on disk and before a built-in package of the same name.

## Threads

A session is used by one thread at a time, and a command is called back on the thread that asked for the document, while it is being made. Separate sessions share nothing but read-only tables and can run side by side.
