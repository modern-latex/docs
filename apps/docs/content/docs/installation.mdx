## From a package

<Callout type="info">
  No release has been published yet. Until one is, build mLaTeX from source as below.
</Callout>

### Packages for each system

Prebuilt packages will be attached to each release on [GitHub](https://github.com/modern-latex/mlatex/releases). Each one is named for its system and architecture, such as `mlatex-x.y.z-windows-x64.msi` or `mlatex_x.y.z_arm64.deb`.

| System  | Packages                  | Installs to                |
| ------- | ------------------------- | -------------------------- |
| Windows | `.msi` installer, `.zip`  | `C:\Program Files\mLaTeX`  |
| macOS   | `.pkg` installer          | `/Applications/mLaTeX`     |
| macOS   | `.dmg`, `.tar.gz`, `.zip` | wherever the folder is put |
| Linux   | `.deb`, `.rpm`            | `/opt/mlatex`              |
| Linux   | `.tar.gz`, `.zip`         | wherever it is unpacked    |

### Installing

<Tabs items={["Windows", "macOS", "Linux"]}>
  <Tab value="Windows">
    ```powershell
    msiexec /i mlatex-x.y.z-windows-x64.msi
    ```
  </Tab>

  <Tab value="macOS">
    ```bash
    sudo installer -pkg mlatex-x.y.z-macos-arm64.pkg -target /
    ```
  </Tab>

  <Tab value="Linux">
    ```bash
    sudo apt install ./mlatex_x.y.z_amd64.deb
    ```

    ```bash
    sudo dnf install ./mlatex-x.y.z-1.x86_64.rpm
    ```
  </Tab>
</Tabs>

### What is installed

The program is `bin/mlatex` inside the installed folder, with the fonts and hyphenation patterns in `assets/` beside it. Add that `bin` folder to your `PATH` to run `mlatex` from anywhere.

### The command's name

The command is named `mlatex` so that it never collides with the `latex` a TeX distribution installs, and the Linux packages stay out of `/usr/bin` for the same reason.

## From a package manager

<Callout type="info">
  These packages are not published yet. The commands below are the ones to use once they are.
</Callout>

### Python

The Python package is `mlatex`, published on PyPI. It carries the C library, `latex_ffi`, and the fonts it reads, for programs that make documents; see [Python](/docs/embedding/python).

<Tabs items={["uv", "pip", "poetry"]}>
  <Tab value="uv">
    ```bash
    uv add mlatex
    ```
  </Tab>

  <Tab value="pip">
    ```bash
    pip install mlatex
    ```
  </Tab>

  <Tab value="poetry">
    ```bash
    poetry add mlatex
    ```
  </Tab>
</Tabs>

### JavaScript

The JavaScript package is `mlatex`, published on npm. It carries the WebAssembly module, `latex.js`, `latex.wasm` and `latex.data`, for web pages, workers and Node; see [JavaScript](/docs/embedding/javascript).

```npm
npm install mlatex
```

## From source

<Steps>
  <Step>
    ### Install the tools

    * CMake 3.25 or later, and Ninja.
    * A C++26 compiler with `#embed`: Clang 19 or later, or GCC 15 or later. On Windows, use the `clang-cl` that Visual Studio installs under `VC/Tools/Llvm`.
    * [vcpkg](https://vcpkg.io), for the libraries.
    * [gperf](https://www.gnu.org/software/gperf/).

    Optional: libcurl on Linux and macOS, for pictures fetched from `https://` addresses (Windows uses WinHTTP), and Doxygen, for the API reference.
  </Step>

  <Step>
    ### Install the libraries

    ```bash
    vcpkg install harfbuzz libpng libjpeg-turbo libwebp zlib
    ```
  </Step>

  <Step>
    ### Configure

    ```bash
    cmake -B cmake-build-release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake
    ```

    On Windows, the `release` preset sets all of this up:

    ```bash
    cmake --preset release
    ```

    If the toolchain file is left out, the build looks for vcpkg in `VCPKG_ROOT`, then in `C:/vcpkg`. On Windows it also picks Visual Studio's `clang-cl` by itself when your IDE profile names MSVC's `cl` or MinGW, neither of which can compile the engine.
  </Step>

  <Step>
    ### Build and test

    ```bash
    cmake --build cmake-build-release
    ```

    ```bash
    ctest --test-dir cmake-build-release --output-on-failure
    ```

    The program is `cmake-build-release/mlatex`. The build also leaves `latex_ffi`, the C library, beside it.
  </Step>

  <Step>
    ### Check it

    ```bash
    mlatex --version
    ```

    ```text
    mlatex x.y.z
    Typesets LaTeX into PDF: one program, no TeX installation behind it.
    ```
  </Step>
</Steps>

## Where mLaTeX finds its fonts

### Walking up from the program

The fonts and hyphenation patterns live in an `assets` folder. mLaTeX looks for it by walking up from the program's own location to the first folder that holds `assets/fonts`, so a build tree, an installed copy or an unpacked archive all work wherever they are.

### --assets

If you move the program away from its assets, name them yourself:

```bash
mlatex --assets=/path/to/assets paper.tex
```

## Making packages

### cpack

From a Release build tree, `cpack` makes the packages for the system and architecture of that build:

```bash
cpack --config cmake-build-release/CPackConfig.cmake
```

### Windows installers

An `.msi` needs WiX: version 3, or the `wix` .NET tool, version 4 or later. WiX 7 asks for its EULA to be accepted once per machine with `wix eula accept wix7`.

### Other architectures

Another architecture is another build, for example `clang-cl` targeting ARM64 with the `arm64-windows` triplet.
